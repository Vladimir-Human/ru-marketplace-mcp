# Пилотный прогон model routing eval — 2026-09-13

> **Single-model pilot, НЕ репрезентативно.** Одна модель, один сэмпл на кейс,
> без измерения латентности. Числа ниже валидируют **конвейер** (промт →
> ответы → детерминированный скоринг → отчёт), а не качество модели.
> Дополнительный дисклеймер: оцениваемая модель — **автор кейсов**
> (агент DSH-сессии на qwen3.8-max-0902), поэтому accuracy 1.0 здесь —
> верхняя граница загрязнённой оценки, а не сигнал о модели. Мульти-модельный
> прогон по протоколу (`MODEL_ROUTING_PROTOCOL.md`) — задача оркестратора.

## Параметры

- Бандл: `work/evals/routing-cases-v1.json` (38 кейсов: 19 routing + 19 error-classification).
- Модель: qwen3.8-max-0902 (DSH-агент, автор бандла).
- Сэмплов на кейс: 1 (протокольный минимум ≥3 — для мульти-прогона).
- Метод: ответы записаны одним проходом по отрендеренному системному контексту
  (каталог скиллов + словарь отказов) **до** открытия скорингового отчёта;
  промпты сгенерированы раннером (`--prompts-out`), id кейсов и expected в них
  не попадают. Остаточная загрязнённость (автор знает собственные ожидания)
  не устранима в self-pilot и честно декларируется.
- Раннер: `uv run python scripts/model_routing_eval.py run --answers work/evals/runs/pilot-2026-09-13-qwen3.8-max-0902-answers.json`.

## Что пилот реально проверил

1. `--help`, режим `run`, режим `matrix` (legacy-контракт cec34a2 не сломан —
   `evaluate()` без аргументов по-прежнему валидирует матрицу).
2. Синтетика точности: все-верно = 1.0, половина = 0.5 (ровно, бандл чётный —
   зафиксировано офлайн-тестом `test_half_correct_answers_score_half`).
3. Рендер промптов: каталог + answer contract + query; id кейса и expected в
   промпт не протекают (тест + `runs/prompts-v1.json`).
4. Скоринг: expected, допустимые альтернативы, forbidden, missing, обёртка с
   метаданными, неизвестные id — все ветки покрыты офлайн-тестами.
5. Per-slice отчёт не схлопнут в одну оценку (eval-matrix: «Do not collapse
   these into one score»).

## Наблюдения автора-оценщика (для мульти-прогона)

- Кейсы, где я сам сомневался при ответе (реальные пограничники для других
  моделей): **routing-016** («ВБ или Озон — сравни только эти две»: одиночный
  источник vs fan-out с фильтром `sources`), **routing-019**
  (`compare_sources` vs `marketplace_sources` — поэтому альтернатива),
  **error-010** (эскалация 429→403 на глубокой пагинации Avito — скилл зовёт
  ожидаемыми оба кода), **error-011** (SmartCaptcha звучит как challenge, но
  скилл явно зовёт её retryable rate-limit), **error-013** (429 из датацентра:
  формально rate_limited, по смыслу «там ничего не проверить» — transport;
  альтернатива заложена).
- Если другая модель систематически отвечает на эти пять кейсов иначе и её
  ответ защищаем цитатой из SKILL.md — по протоколу (п.6) правится кейс, а не
  оценка модели.
